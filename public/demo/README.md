# DEMO MALL × CodiPOP

영세몰 제휴 설득용 **웹 데모**입니다.

흐름: 몰 상품 상세 → **착용해 보기** → 내 사진 피팅 → 결과 → **이 상품 구매하기**(몰 복귀)

## 실행

### 로컬 (본인 PC만)

```bash
yarn demo-mall
```

`http://localhost:5173`

### 외부 공유 (다른 사람에게 보여줄 때)

Render 백엔드에 배포된 주소:

**https://codipop-backend.onrender.com/demo/**

이 링크를 카톡/메일로 보내면 됩니다.

## 데모 시나리오 (몰 사장님 앞에서)

1. 홈에서 상품 카드 선택
2. 상세 이미지 위 **착용해 보기** 탭
3. **체험용 사진 쓰기** 또는 본인 사진 선택
4. **AI 피팅 시작** (백엔드 `codipop-backend.onrender.com/try-on` 호출, 약 3~10초)
5. Before / After 확인 후 **이 상품 구매하기**

## 파일

| 파일 | 역할 |
|---|---|
| `index.html` | 화면 골격 |
| `styles.css` | 몰 상세 + 위젯 스타일 |
| `app.js` | 라우팅·피팅 API 연동·이벤트 수집 |

| `admin.html` / `admin.css` / `admin.js` | **사장님용 MD 대시보드** |
| `assets/` | 샘플 상품/인물 이미지, 몰 로고 |

## MD 대시보드

- 로컬: `http://localhost:5173/admin.html`
- 배포: **https://codipop-backend.onrender.com/demo/admin.html**

`GET /my/stats` 하나만 호출하며, 사업기획서 슬라이드 21에서 사장님이 요구한
5개 항목을 그대로 화면에 올립니다 — 피팅 횟수(전체/1인당), 피팅 후 판매 연결(횟수/금액),
가장 많이 입어본 옷, 피팅 후 구매 순위, 업셀링. 여기에 청구 근거(등급별 건수·원가)를 더했습니다.

**"피팅했지만 사지 않은 상품"이 이 화면의 핵심입니다.** 쇼핑몰이 어디서도 얻을 수 없는
신호이며, 절대 건수가 아니라 **미구매율** 순으로 정렬합니다 — 절대 건수로 줄 세우면
인기 상품이 위로 올라와 실제 문제 상품이 묻힙니다.

### 화면에 쇼핑몰 ID 입력칸이 없는 이유

**볼 수 있는 몰은 조회 토큰이 정합니다.** 입력칸이 있으면 사장님이 남의 몰 ID 를
넣어볼 수 있고, 실제 몰의 매출 데이터가 들어간 뒤에는 그 순간이 사고가 됩니다.

- 사장님은 발급받은 **조회 토큰**만 입력합니다 (`sessionStorage` 에만 보관)
- 서버가 토큰으로 몰을 판정하므로 남의 몰은 열리지 않습니다
- `?mall=` 파라미터는 **우리 마스터 토큰으로 들어왔을 때만** 인정됩니다 (내부 확인용)

상품은 이제 `top-01` 이 아니라 **상품명**으로 표시됩니다 — 위젯이 상품명을 함께
보내주므로 몰 상품 API 연동 없이도 채워집니다.

> 영업 시연 시 몰 홈 하단의 `사장님 리포트 →` 링크로 바로 이동할 수 있습니다.

> `size-recommend.js` 는 앱의 `src/services/sizeRecommendService.ts` 를 그대로 옮긴 것입니다.
> **앱과 데모가 같은 사이즈를 추천해야 하므로 한쪽만 고치지 마세요.**

## 프리 사이즈 대응 (`product-size.js`)

실제 파일럿 후보 몰의 사이즈 표기입니다.

| 몰 | 표기 |
|---|---|
| 리린 | `[size:F(55~66)]` |
| 저스트원 | `FREE` / `FREE,L` / `S,M,L` |

우리는 `XS~XXL` 로만 답하는데, 이 상태로 리린 상품에 "L 사이즈를 추천합니다"라고 하면
**애초에 L 이 없는 상품**입니다. 사장님 앞에서 바로 들통납니다.

`product-size.js` 는 BMI 규칙(`size-recommend.js`)의 결과를 **상품이 실제로 파는
사이즈로 번역하는 층**입니다. 규칙 자체는 건드리지 않으므로 앱과 계속 같은 값을 냅니다.

**원칙: 상품이 팔지 않는 사이즈는 절대 추천하지 않는다.**

| 상품 표기 | 내 추천 | 화면에 나오는 말 |
|---|---|---|
| `F(55~66)` | M | "잘 맞는 사이즈입니다 — 범위 안에 들어옵니다" |
| `F(55~66)` | XL | "타이트할 수 있습니다 — 기준이 55~66인데 추천은 88" |
| `S,M,L` | XL | "77(L) 사이즈를 추천합니다 — 가장 가까운 작은 사이즈" |
| `FREE` | 무관 | "프리 사이즈 상품입니다 — 실측을 함께 확인하세요" |

> 숫자 뒤 조사는 읽는 법에 따라 달라집니다(`55라` / `66이라`).
> 문구에서 조사를 빼고 괄호와 `입니다` 로만 쓴 이유입니다. 수정할 때 주의하세요.

## Phase 1 기능 (2026-08-08 추가)

| 기능 | 내용 | 근거 |
|---|---|---|
| **사이즈 추천** | 키·몸무게·평소 사이즈 → BMI 보정으로 추천 사이즈 제시. 상품 표기 사이즈와 비교 | 반품 사유 1위가 사이즈·핏 불만족인데 이미지 합성만으로는 답이 안 됨 |
| **믹스매치 업셀링** | 결과 화면에 어울리는 상품 제안 → `함께 피팅`으로 옷 2벌 동시 착장 | 기획서 슬라이드 13 |
| **브랜드 워터마크** | 결과 이미지에 **로고를 서버에서 굽는다** (`mallLogo` 전송) | 슬라이드 11 — 저장·공유해도 남아야 의미가 있음 |
| **저장 / 공유** | 이미지 저장, Web Share API (미지원 시 링크 복사) | 슬라이드 11 바이럴 |
| **Before 숨김** | 결과는 After 단독 노출, `원본 보기` 토글로 전환 | 슬라이드 21 "비포 필요없음" 피드백 |

전부 추가 AI 비용이 **0원**입니다. 사이즈 추천과 믹스매치는 규칙 기반이고,
워터마크는 합성 결과에 얹는 후처리입니다.

## 제휴 몰용으로 바꿀 때 (추가)

`app.js` 상단의 `MALL_ID` / `MALL_NAME` 을 실제 몰 값으로 바꾸면
통계 집계 단위와 워터마크 문구가 함께 바뀝니다.

워터마크는 `assets/mall-logo.png` 를 제휴 몰 로고로 교체하면 됩니다.

> ⚠️ **한글 몰명은 반드시 로고 이미지로 넣으세요.**
> 운영 서버(Linux)에 한글 폰트가 없어 텍스트 워터마크로는 글자가 깨집니다
> (실제로 "리린"이 네모로 출력되는 것을 확인했습니다).
> 로고는 제작 시점에 글자가 이미지로 고정되므로 서버 폰트와 무관합니다.
> 흰색 계열 PNG(배경 투명, 가로 500~1000px)를 권장합니다.

## 제휴 몰용으로 바꿀 때

`app.js`의 `PRODUCTS`에서:

- `image` → 실제 상품 이미지 경로/URL
- `buyUrl` → 실제 상품 상세 또는 장바구니 URL (`https://...`)

`buyUrl`이 있으면 **이 상품 구매하기**가 그 주소로 이동합니다.

## 이 데모와 임베드 위젯의 관계

| | `demo-mall` (이 폴더) | 임베드 위젯 (`codipop-backend/public/widget/`) |
|---|---|---|
| 용도 | **영업 시연** — 몰 전체 흐름을 우리가 만들어 보여줌 | **실제 납품** — 몰 페이지에 스크립트 한 줄 |
| 상품 | `app.js` 의 `PRODUCTS` 하드코딩 | 몰 페이지의 `data-codipop-*` 속성에서 읽음 |
| 옷 이미지 | 브라우저가 파일로 전송 | **URL 만 보내고 서버가 받아옴** (몰 CDN 은 CORS 로 막힘) |
| 인증 | `mallId` 문자열 | `apiKey` (`pk_...`) |

**연동 예시 페이지: https://codipop-backend.onrender.com/widget/example.html**
고객사에는 이 링크를 보냅니다. 붙일 코드와 속성 설명이 전부 들어 있습니다.
